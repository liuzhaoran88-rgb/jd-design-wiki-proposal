relay-to-design-md 定义

把 Relay 设计稿一键转成结构化、token 化、可 review 的 design.md。设计师传一个 Relay URL，零输入零选择题，自动反查 V16 token、自动维护双向追溯索引、自动 flag 视觉问题。

行为准则

  1. 零输入：只接受 1 个 Relay URL 参数，不弹问、不选项
  2. 自动推断：level / bg / slug / name_zh / name_en 全部从节点信息推断，5 处 TODO placeholder 留给设计师手填
  3. 双向追溯：design.md ↔ INDEX.md ↔ Relay sharedPluginData，三处任一改动都能反向定位
  4. 不依赖聪明模型：全部判断走 references/ 查找表，结果可预测、可回放

relay-to-design-md 类型

本节选写。当前 skill 只有单 URL 手动调用一种形态，无需分类。

relay-to-design-md 结构

Skill 包内 16 文件 / 2500+ 行，分 4 大块：

区块 关键文件 职责
入口 SKILL.md 触发条件、调用方式、整体工作流说明
references/ token-reverse-lookup / slug-pinyin-fallback / node-type-mapping / auto-detect-rules / frontmatter-spec / traceability / checklist / bg-mapping.json / variant-vocab.json 查找表 + 规则库 + 受控词表，skill 所有判断都基于这一层，不靠模型瞎猜
templates/ component.md design.md 输出模板
bin/ validate.sh · sync-index.sh 提交前 frontmatter 校验 + INDEX.md 自动重建（macOS bash 3.x 兼容）

设计属性

输入：1 个 Relay URL，形如 https://relay.jd.com/file/design?id=...&page_id=...&node_id=...

输出：

  • jd-design-system-md-v16/<level>/<bg>/<slug>/design.md —— token 化的规范源
  • 同目录 preview.png —— 自动导出的节点截图
  • Relay sharedPluginData('jd-design-wiki', ...) 写回 —— Relay 端反查仓库路径
  • INDEX.md 自动追加 —— 仓库视角的全量索引

跨文件契约：uses_components ↔ used_by 互链；validate.sh 检测断链。

错误示例

❌ 不要这样用 relay-to-design-md：

  1. 把它当 design-review 用 —— 本 skill 不审计合规，那是 design-review 的事
  2. 把它当 design-md-to-site 用 —— 本 skill 不渲染对外站点，那是 design-md-to-site 的事
  3. 跨 Relay 文件批量调 —— 本 skill 一次只处理 1 个 URL；批量需要在外层包脚本
  4. 跳过 review 就 commit —— skill 留了 5 处 TODO placeholder 给设计师手填，validate.sh 会 block 未填的提交
